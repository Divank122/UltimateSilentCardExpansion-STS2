# 正式版语言诊断日志

USCE 内置被动诊断，随模组加载启用，不需要额外安装诊断模组。它只观察，不切换语言、不补写翻译、不改变卡牌或联机数据，也不主动联网上传。记录写入游戏原有日志，统一标记为 `[USCE.Language]`。

## 玩家反馈时需要什么

出现中英文异常切换后，请尽快退出游戏，保留并发送 `%APPDATA%\SlayTheSpire2\logs\godot.log`；若已经重开游戏，也请保留同目录对应时间的 `godot*.log`。自定义用户数据目录的玩家应在自己的用户数据目录下查找 `logs`。

同时说明大致发生时间、单人还是联机、受影响的卡牌或界面。日志可能包含游戏及其他模组原本记录的信息，建议私下发送给作者。

## 记录内容

- `initialized`：游戏版本、已加载模组 ID/版本、USCE DLL 构建标识，以及相关翻译表的条目数和内容指纹。构建标识可区分版本号相同但 DLL 不同的构建。
- `languageRequested` / `languageApplied`：全局语言切换请求、调用方法链、实际应用的语言；模型初始化后还会比较翻译表，记录相对启动时缺失的条目数与少量示例。
- `tableMerge`：模型初始化后，有代码通过游戏 MergeWith 接口写入 USCE 翻译条目，记录表名、少量键及调用方法链。正常语言加载也可能产生此记录。
- `rawTextChanged` / `missingText`：USCE 原始翻译文本相对上次读取或启动基线发生变化，或返回缺失键占位。文本片段截断到 180 字符，同时保留内容指纹。
- `uiScriptChanged` / `uiLanguageMismatch`：实际 USCE 卡牌控件的标题或描述出现汉字有无变化，或首次显示时与中文/英文语言设置不符。
- `hookUnavailable` / `snapshotUnavailable`：当前游戏版本无法安装某个观察点或读取快照；相应诊断退化，不阻止模组继续加载。

记录附带日志顺序、当前语言、单人/房主/客户端状态（无进行中对局时为 `no-run`）及线程编号。调用栈只保留方法名，不附本地源文件路径。该模块不读取玩家平台账号 ID、聊天内容或完整存档。

## 正式版开销和边界

每次游戏进程启动最多 64 条结构化记录，最多 12 条包含调用方法链；达到上限后再写一条提示并停止观察。缓存最多各保存 512 个文本键、卡牌 ID 或缺失键。正常重复读取相同文本不会反复记日志，伤害/格挡等数字刷新不会单独触发 UI 记录。

所有观察回调都有异常隔离，日志写入有重入保护。诊断没有定时轮询，也不单独创建日志文件。

UI 检测使用汉字有无作为线索，不是翻译正确性的判定。混合语言可能是正常专名或其他模组追加内容；语言切换后的文本变化也可能完全正常。读取时捕获的调用链指出读取者，只有切换请求和 MergeWith 调用链直接指出相应修改入口。未经过这些接口的直接字段修改，需要结合后续文本/UI 记录分析。超过日志预算后发生的异常可能不会被记录；无诊断事件不能证明没有问题。

本改动不修复已确认的语言表重载丢失文本或合成牌中文前缀问题，以免诊断与修复混在一起改变待调查现象。
